# ADR-001: Wybór sposobu pobierania danych dla datasetu `crossborder_physical_flows`

**Status:** Accepted  
**Data:** 2026-02-08  
**Zakres decyzji:** Implementacja datasetu crossborder_physical_flows

## Kontekst

W ramach rozwoju pipeline pojawiła się potrzeba dodania datasetu reprezentującego **fizyczne przepływy transgraniczne energii elektrycznej** pomiędzy Polską a wybranymi obszarami sąsiednimi.

ENTSO-E / biblioteka `entsoe-py` udostępnia więcej niż jedną metodę pobierania tego typu danych, co wymagało podjęcia świadomej decyzji architektonicznej co do:
- używanej metody API,
- modelu iterowania po obszarach,
- sposobu obsługi braków danych,
- stabilności struktury danych w czasie.

Decyzja dotyczy **wyłącznie** implementacji datasetu `crossborder_physical_flows`.

## Decyzja

### 1. Wybrana metoda API

Zdecydowano się na użycie metody:

`EntsoePandasClient.query_crossborder_flows(from_area, to_area, start, end)`

czyli pobieranie danych **per para obszarów i per kierunek**.

### 2. Odrzucona alternatywa

Świadomie **nie użyto** metody pobierającej wszystkie granice naraz (np. warianty typu *all borders*), mimo że teoretycznie pozwala ona na mniejszą liczbę zapytań.

Powody odrzucenia:
- metoda ta zwraca zmienną liczbę kolumn zależną od dostępności danych,
- struktura kolumn może różnić się pomiędzy dniami,
- znane są przypadki błędów przy braku danych dla wszystkich granic jednocześnie,
- utrudnia to utrzymanie deterministycznego kontraktu datasetu oraz późniejsze łączenie danych.

Priorytetem projektu jest **stabilność struktury danych i odporność na zmiany API**, nawet kosztem większej liczby zapytań.

### 3. Model iteracji po obszarach

Przyjęto model:
- jeden obszar bazowy: `PL`,
- osobna lista `counterpart_areas` tylko dla tego datasetu,
- pobieranie danych dla obu kierunków:
  - PL → X
  - X → PL

Brak danych dla danej pary lub kierunku skutkuje jej pominięciem, bez wpływu na resztę datasetu.

### 4. Lista obszarów

Dla datasetu `crossborder_physical_flows` ustalono następującą listę obszarów:
- DE, CZ, SK, SE, LT, AT, UA

Ukraina traktowana jest identycznie jak pozostałe kraje — potencjalny brak danych nie jest traktowany jako błąd.

### 5. Stabilność formatu danych

Ustalono, że:
- dataset zawsze zwraca `pandas.DataFrame`,
- odpowiedzi typu `Series` są jawnie konwertowane,
- przypadki wielokolumnowych odpowiedzi dla jednej pary są pomijane.

Decyzja ta ma na celu zabezpieczenie pipeline przed zmianami zachowania biblioteki `entsoe-py` w przyszłości.

## Konsekwencje

- Implementacja jest spójna z istniejącymi datasetami opartymi o wymianę pomiędzy obszarami.
- Pipeline zachowuje deterministyczny kontrakt kolumn.
- Projekt unika ryzyk związanych z niestabilnymi odpowiedziami API kosztem większej liczby zapytań.
- W przyszłości łatwo odtworzyć **dlaczego** wybrano taki, a nie inny sposób pobierania danych.
